# Shipped Alembic revision ids — APPEND-ONLY (issue #2086).
#
# Every id that has ever reached a released image goes here, and once added
# it NEVER moves or disappears — this file only grows. Landing an id here is
# a promise: some database, somewhere, may already have exactly this string
# stamped in its `alembic_version` table.
#
# Renumbering or deleting a shipped id breaks that promise. `ScriptDirectory`
# stops recognizing the id an already-migrated database is sitting on, so
# `src/db_pg.py::assert_pg_at_head`/`ensure_pg_at_head` can no longer tell a
# genuinely stranded (renumbered-away) database from one that is merely AHEAD
# (an app rollback after a newer image already migrated) — and no image, past
# or future, knows how to move a stranded database forward. This happened for
# real: `facts_ingest_runs` shipped as `0077_facts_ingest_runs`, then got
# renumbered to `0078_facts_ingest_runs` when a parallel `0077_ontology_drafts`
# migration merged first and claimed that number. Every database that had
# already applied the old id was stranded — see
# `RENUMBERED_REVISION_REPAIRS` in `src/db_pg.py` for the repair, and
# `docs/migrations.md` → "A database stranded by a renumbered revision" for
# the operator runbook. `0077_facts_ingest_runs` itself is NOT listed below —
# it no longer resolves in the current chain by construction, so it cannot
# pass rule (a) below; it lives only in the repair map.
#
# `tests/test_alembic_revision_ratchet.py` enforces this from both directions:
#   (a) every id below must still resolve via `ScriptDirectory.get_revision` —
#       a renumber or delete fails this test.
#   (b) every id in the live migration chain (`ScriptDirectory.walk_revisions`)
#       must be listed below — a new migration that forgets to append its id
#       fails this test until the line is added.
#
# Insert new revisions at the HEAD of the chain — never renumber or reuse an
# id that has already shipped, even if it never reached production; if two
# branches collide on the same number, keep both authors' original ids and
# rebase the down_revision (a merge revision if both are heads), as later
# entries below (0045/0049/0051/0057/0059/0085/0086/0087/0088/0094/0096 each
# have more than one id sharing a numeric prefix) already do.
#
# Comment lines (like this one) and blank lines are ignored. One revision id
# per line otherwise. Order is chain order (oldest first) for readability
# only — the tests treat this as a set.
