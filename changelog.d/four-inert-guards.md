### Fixed
- **"Test sign-in" on `/admin/server-config` now reads as unavailable when there is no config to test, and says why.** A legibility fix, not a security one — worth stating plainly, because the finding it came from reads as the latter. The route is gated server-side and always was: `?mode=test` raises `403` without an admin session and redirects to `/login?error=sso_not_configured` when `is_configured()` is false (`app/auth/providers/sso.py:529-535`), so clicking it on an unconfigured or DuckDB instance never started a sign-in — it bounced to an error page. What was broken is that the control looked live: it is an `<a>`, so neither disable reached it. The 501 branch (SSO needs the Postgres app-state backend) sweeps `#sso-section input, #sso-section button`, which an anchor is in neither of, and the healthy path toggled a `btn-disabled` class **that no stylesheet in the repo defines** — a guard written once and inert ever since. Both branches now use the convention that already existed (`aria-disabled`, which the `ds.button` macro emits) plus `tabindex="-1"`. The gate is deliberately keyed on `configured && has_client_secret` and **not** on `enabled`: test mode is designed to work before SSO is switched on, which is its entire purpose. The shared `.btn[aria-disabled="true"]` rule gains `pointer-events: none` — `opacity`/`cursor` alone stop a `<button>` because the browser refuses the activation, and stop nothing at all on an anchor, which is why two pages had already patched that in locally. **The reason lives on a wrapper `<span>`, never the anchor:** `pointer-events: none` also removes the element from hit-testing (confirmed in Chromium — `elementFromPoint` over the link does not return the link), so a `title` on the `<a>` itself can never be shown, and the first cut of this fix put it there — disabling the control and hiding why, on a theme whose whole point is that a refusal carries its exit. Guarded by parsing the CSS declaration rather than grepping for a class name, since the original bug *was* a class name present in the source with no rule behind it.
- **A metric's description no longer prints twice on `/semantic-layer`.** `trimRedundantDescriptions` — whose whole job is hiding a detail panel that only repeats the row above it — selected `.sl-item[data-cat]`, and no `.sl-item` has ever carried `data-cat`; that attribute name belongs to the filter menu's `.fbar-cat` categories. It matched zero rows and had been a no-op. Now selects `[data-tab]`, which both row kinds actually carry. The guard runs the shipped function against a DOM shim that answers only the live selector, because the broken one was present, plausible, and invisible to any source-grep test.
- **The Library's "N more in <other tab>" notice reads the filters correctly.** Two defects in the two lines that decide whether the reader is looking for anything: a bare space counted as a search (`!!el.value`, untrimmed), so typing one character and deleting it left the notice offering to carry a query nobody made; and the active-filter check read only the Filter menu's checkboxes, never `#lib-stack-toggle`, whose state lives in `aria-pressed` because it is a `toggle` facet declared with a `control` and rides the bar rather than the menu — so the notice stayed silent for the facet most likely to hide rows.
- **`_get_local_dev_user` refuses off `LOCAL_DEV_MODE` in its own body, not only in its docstring.** It looked the configured address up and returned whatever it found, so on a deployment that happens to hold an account at `get_local_dev_email()` it answered with a real principal in any mode. Survivable while every caller sat inside an `if is_local_dev_mode():` block; not survivable once the view-as work made this function's answer decide whether a ticket with no verifiable session behind it is accepted, at which point one `if` at one call site was the only thing in the way. All three existing callers already gate on the mode, so this is a no-op for them and closes the gap for the next one. The prior coverage could not have caught it — every test of that fallback monkeypatches `local_dev_viewer_id`, pinning what the consumers do with an answer rather than that the function declines to give one.
