### Fixed
- **`agnes admin activity` and the `activity` MCP tool can now page past the first window of rows.** The Activity Center timeline endpoint has always paginated (`next_cursor`), but neither agent-facing wrapper had a way to send it back — the CLI's own hint suggested `--limit higher`, which cannot work past the 200-row cap. `agnes admin activity` gained `--cursor` (takes the `next_cursor` object printed by a prior `--json` call verbatim) and the hint now names it; the `activity` MCP tool gained `cursor_ts`/`cursor_id`, forwarded to the server only when both are set.
- **A half-empty pagination cursor no longer silently restarts the timeline from page one.** `agnes admin activity --cursor '{"ts": "", "id": ""}'` and the `activity` MCP tool with only `cursor_ts` or only `cursor_id` set now fail loudly (a clean CLI error / a `ValueError` naming the missing half) instead of quietly re-reading the first page.
- **A paged `GET /api/admin/activity` read can no longer skip rows when it spans a wall-clock boundary.** `since_minutes` computed a fresh floor on every call, so a row that sat inside the first page's window could fall out by the time a later page was fetched. `next_cursor` now carries the floor the first call computed (`since_ts`); `agnes admin activity`, the `activity` MCP tool, and the Activity Center web page all forward it automatically on a continuation, pinning the whole paged read to one window. Omitting it keeps the prior (relative-floor) behavior for any existing caller.
