### Fixed
- **A transcript could be reported current against a session snapshot that was already out of date.** The on-demand check read the session row, then did an owner lookup and a file check before deciding; a message committed inside that window left the existing export matching the older snapshot, so it was served as confirmed-current. The decision is now confirmed against a session read taken at the moment of certifying, and a session that has moved on is re-exported rather than merely labelled behind.
- **A slower export could replace a newer transcript with an older one.** Publishing the transcript and its watermark is atomic per file but orders nothing between writers, so an export that read fewer messages could still land last. An export whose snapshot adds nothing to what is already on disk now leaves it alone.
- **A transcript could be reported as confirmed-current while what was actually shown was an older copy.** The freshness check and the render were two independent reads of the same file, so anything that rewrote it in between — the periodic sweep, another export — was what got rendered, under a verdict made about content nobody looked at. The transcript is now read once, and the verdict travels with those exact bytes; when they are not the ones that were checked, the response says so instead of claiming verification.
- **The transcript viewer could report a transcript as confirmed-current using a checksum taken from a different copy than the one it verified.** The checksum it reports against came from a separate re-read of the coverage record after deciding the export was current, so an export finishing in that instant supplied the checksum of a copy nothing had compared against the conversation — and the viewer, matching the bytes it then read against that checksum, called it verified. The checksum now comes from the same read that produced the verdict.

### Internal
- Verifying that a transcript and its coverage record belong together always reads and hashes the transcript. A size-and-modification-time pre-check was tried to avoid that on an unchanged file and removed again: those two values are not proof that a file is the same file, so a replacement preserving both — routine where a filesystem keeps coarse timestamps — made the check skip the verification and trust the wrong pairing for as long as the metadata kept matching. Measured, the check costs 0.36 s per sweep tick for 200 transcripts of 2 000 turns each, against a cadence of minutes.
