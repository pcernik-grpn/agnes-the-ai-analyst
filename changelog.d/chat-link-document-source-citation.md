### Added
- **A `document:` source citation now links to the actual file, when the caller can access it.** Chat's "Sources" chips already linked a `table:`/`metric:`/`glossary:` claim to its catalog/semantic-layer page; a `document:` claim stayed a plain label because its ref is a filename as the model wrote it, not a stable id. Resolution now happens server-side (`app/chat/document_links.py`): a citation's ref is matched against the caller's own accessible collections plus any file individually granted to them (`CorpusFilesRepository.match_filenames`, new on both backends — the same `can_parent OR file_granted` authorization `library_file_detail` already uses), and a chip links to `/library/{slug}/f/{file_id}` only when exactly one accessible file matches — an ambiguous or absent match still renders as a label, never a guess.
