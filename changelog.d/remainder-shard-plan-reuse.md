### Fixed
- **A SharePoint connection's already-persisted shard plan is no longer served back verbatim once it predates the "remainder scoped to the scope's own subtree" fix.** The remainder-scoping fix below only corrected how a plan is *computed*; a connection that had already been planned before it shipped kept its stale, pre-fix plan — folder scopes' remainders still pinned at the whole drive root — because plan reuse only checked whether the scope set had changed, never whether the persisted shape was still trustworthy. Observed live: a 388-folder-scope connection sharing one drive, already planned once before the fix deployed, kept re-enqueueing the same 388 whole-drive-root remainders on every later trigger. A persisted plan whose remainder targets show that stale shape is now discarded and rebuilt on the next trigger, same as a scope-set change; a genuinely whole-drive scope's own remainder (`root_item_id=None` is correct there) is unaffected.
