### Fixed
- **A hosted data app that had gone to sleep offered a viewer no way to open it.** The app pages rendered the app's URL as a clickable link only when its state was exactly `running`, and as inert `<code>` text otherwise — but the ingress proxy serves a viewer from `sleeping` and `deploying` too: a sleeping app is woken on request for anyone allowed to see it, and a deploying one gets the holding page. Idle apps are parked in `sleeping` by the idle reaper, so the normal resting state of every hosted app was also the state whose URL looked dead. For someone with a view grant that was a dead end rather than an inconvenience: the endpoint that restarts an app is owner/Admin-only, so they could neither open the app nor deploy it, and the page gave them nothing to click. The clickability decision now reads one shared set of proxy-serveable states (`REACHABLE_STATES`, surfaced per app as `reachable`) instead of each template restating it, and a test pins that set against what the proxy actually answers per state so the two cannot drift apart again. The same field also stops offering a link on a deployment that cannot serve hosted apps at all — neither `data_apps.subdomain_base` nor `data_apps.allow_same_origin` set, where the proxy's origin gate refuses every hosted app before it ever looks at state, a `running` one included; that condition already had a startup warning and is now a single shared predicate rather than a second copy of the rule.
