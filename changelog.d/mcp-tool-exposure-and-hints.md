### Fixed
- **`effective_access` no longer errors on the exact question it exists to answer.** Asking about a table you cannot see used to raise `Error executing tool effective_access` — a wrong id and "you have no access" got the same tool-execution error card. It now returns a normal `{"table_id", "granted": false, "note": ...}` answer for both cases (deliberately still indistinguishable from each other, so the tool can never be used as an existence oracle for a table you may not know about).
- **`admin_source_connections_list` no longer raises a raw `403` for a non-admin caller.** This tool cannot be filtered out of a non-admin's static MCP tool list, so it now answers cleanly instead — `{"connections": [], "admin_required": true, "reason", "note"}` — and names the real reason when the caller is an admin who has merely paused their own elevation.
- **`data_apps_list` (both the SSE/streamable and the stdio MCP tool) no longer raises a raw `404` when data apps are disabled on the instance.** It now returns the same friendly `data_apps_disabled` payload the other data-app tools already use, instead of a tool-execution error.
- **The `activity` MCP tool no longer forwards a `since_minutes` past the server's 30-day cap and surfaces the resulting `422` validation dump as a tool error.** A value above the cap is now clamped locally, and the response carries `since_minutes_clamped: {"requested", "used"}` so the caller knows a narrower window was actually used.
