Allowed transitions

  • duckdb → side-car — first cutover to in-container Postgres.
  • duckdb → cloud — first cutover, skipping side-car.
  • side-car → cloud — graduate from container to managed Postgres.
  • cloud → side-car — move back to container (DR, cost, or retiring the managed instance).
  • No path back to DuckDB yet. The state machine documents reverse migration (side_car/cloud → duckdb) and the platform supports multi-destination transitions in either direction, but the migrator does not implement it — /api/admin/db-state/migrate answers 501. Until it lands, treat the DuckDB file as the recovery backup rather than a writable target.
