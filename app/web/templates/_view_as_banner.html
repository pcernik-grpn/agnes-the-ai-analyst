{# Read-only view-as banner — every page, no page opt-in. Included once from `base_ds.html` (and legacy `base.html`) rather than composed into any layout, the same way `_dev_preview.html` is: a mode this persistent must not depend on a page remembering to render it, and it must not consume layout space a page had to leave for it. `view_as_state()` is a Jinja global (registered in app/web/router.py) that reads the request-scoped ticket stamped by ViewAsReadOnlyMiddleware — so the banner is present on exactly the requests that are frozen read-only, with no per-page context key to forget. If it is showing, mutations are refused; if mutations are refused, it is showing. The exit control is a POST form carrying the `web_csrf` double-submit token (security playbook §10) — leaving is a state change, so it is not a link. The token is read server-side from the caller's own HttpOnly cookie; the entering POST guarantees one exists. It carries NO destination. The form posts only the token, and the exit route reads where to land from the signed ticket (`app.auth.view_as.return_path`). It used to post this page's path back as `next`, which read as "return where you are" and behaved as "abandon the admin wherever they stopped, as themselves, with the person they were investigating forgotten" — a banner on page five of a browse cannot know the page the mode was entered from, and only the ticket does.
