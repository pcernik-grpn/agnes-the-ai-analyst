{# CSV / files — honest guidance: there is no CSV connector. Files enter through Library Collections (per-file ingestion); a live system's export belongs in a data package instead. #}

Files become searchable through the Library, not a connector.

Upload documents (PDF, Markdown, CSV, …) into a Collection in the Library — {{ instance_brand or 'Agnes' }} ingests them per file and analysts search them with citations. A Collection is honest about being a snapshot: when the content changes, a person re-uploads.

{# A CSV or spreadsheet is the exception, and the pane used to bury it: `src/ingest/tabular.py` registers an uploaded tabular file as a real queryable table, so an instance with no warehouse behind it is NOT tableless — which is exactly the conclusion an admin drew from the heading above. #}

A CSV or Excel file is also a table. Upload one to a Collection and {{ instance_brand or 'Agnes' }} registers it as a queryable table you can bundle into a data package and share, the same as a warehouse table — so an instance with no warehouse behind it still has tables.

If the file is an export of a live system, that system is the source — connect it (Keboola or BigQuery) and let a data package carry the tables, or the copy starts drifting the moment it lands. The trade-offs: Collections vs. data packages.
