What does a user see when the corporate brain knows something they aren't allowed to read?

Open. TCRD-207 decides it once for all nine surfaces. The sharpened version — a fact with two sources, one readable — is at the foot of this page.

What it is today

One flat tree, fifteen resource types deep, a row per resource. It grows with the instance rather than with the decision — and it presents a table row with the same weight as the package row that actually puts that table in someone's stack.

One group, opened

Click a line, or arrive on a link from /admin/tables or a package's Share panel, and the group opens in place. The rest stay one line each — so the group above and below are still there to compare against, which is the thing the pane could never do.

Typing is how you open things

One control, not two. The search in the header is the filter — and it is what expands groups, so the collapsed default and the search are one mechanism rather than two competing ones. A group opens because it matched, showing only the rows that matched.

That is also the answer at sixty synced groups, where scrolling stops being a way in: you type, and the three or four that matter open themselves.

Why not two panes

The old layout had one failure underneath the cramping: it answered one question out of three. Master-detail on groups means “who gets Revenue Core?” and “why can Maria see this?” both start with a hunt for the right group to click — and comparing two groups costs you your place. It also spent a fifth of the width permanently on navigation used for two seconds, then squeezed the dense part into what was left.

So the switch does the navigating. It is the same device the Library uses for By subject / By type / Everything, and it means the page can be entered from any of the three directions an admin actually arrives from. Here is the second one.

Why the tier is not an access control

features.stack_auto_membership has been default-on since Wave 0 — the redesign preset is the only preset, and it implies the flag (app/instance_config.py:632). So the grant is the membership: everyone in the group can query the package the moment it is granted, and there is nothing for the analyst to add.

What the tier decides is narrower. Required — permanent, always downloaded. Available — the person gets exactly one choice, keep a local copy or don't. Server-side query works either way; a local copy is speed, not access.

Which is why the words on both ends have to be the same words. docs/RBAC.md still calls auto-membership opt-in — stale, and worth one line, because it is the document this definition rests on.

One control, three names

Nothing in the repo catches this. The design-system contract tests police colour and tokens; no test reads language. Sixteen of the twenty-six open DR(agnes) reviews carry a naming collision, and this is the one that decides whether a person can stop worrying about a resource.

Facts, not just documents

The Library redesign leaves one question open — whether nodes and edges land in Agnes or stay behind the MCP server — and it reaches this page either way, because the same redesign promises every fact traces to a verbatim quote in a source document.

The rule that follows from grant-scoped search: a fact is visible if you can read at least one document that evidences it. Nothing new to grant; the graph inherits document grants. Which produces the case worth deciding with the picture in front of you.
